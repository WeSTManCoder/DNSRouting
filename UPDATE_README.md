# OpenWrt automatic updates

* `AutoUpdate = true` in `/etc/config/dnsrouting/settings.ini` (default on, including when omitted).
* Automatic checks: on service startup, then every 24 hours; successful updates restart the procd service.
* UI: check for updates and confirm install; updates use the same PHP endpoint.
* Update server: deploy `update-server/updates.php` as `/updates.php` and `latest.txt` in the same directory. Upload matching binary files to `/releases/VERSION/dnsrouting-linux-ARCH`. Use HTTPS with a valid trusted certificate; PHP must have file read permissions. Make sure nginx/Apache serves the release binaries.
* **Publish the compiled new version's binary first, then update latest.txt.** Version must be greater than running version. Each release must update `version/version.go`; the provided sources declare v1.0.10 until a release is made.
* Cross-build e.g. `GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o dnsrouting-linux-arm64 .`. For MIPS build with `GOMIPS=softfloat`, manually ensure your runtime architecture key matches: current updater reads `GOMIPS` from the process environment; without it the default key is `mips` or `mipsle`.
* Install binary at `/usr/bin/dnsrouting` with write permissions for the running service. Set up OpenWrt procd init script from `openwrt/dnsrouting.init` as `/etc/init.d/dnsrouting`, `chmod +x`, and enable the service. Downloads go to `/tmp/dnsrouting-update-*` (RAM-backed tmpfs); SHA-256 is checked before installation. After verifying SHA-256, a detached installer stops the service, removes the old binary, writes the new binary directly from `/tmp` to its final location, and starts the service. No `.bak` and no on-flash staging file are created. The process is NOT atomic: if the copy runs out of space or fails, the service will remain stopped and the verified download will remain in `/tmp/dnsrouting-update-*` for manual recovery. Before stopping the service, the updater checks the destination filesystem (flash/overlay) has room for the **entire new binary plus a 256 KiB reserve**. The detached installer checks again immediately before stopping the service. If either check fails, the existing binary and service are left untouched. This is intentionally conservative: space potentially reclaimed by deleting the old binary is not counted, since it may reside in squashfs/ROM. Concurrent writes and filesystem overhead still mean it cannot guarantee that copying succeeds. If the old executable is in squashfs/ROM, deleting it only creates an overlay whiteout and does not free ROM space.
* The update endpoints on port 4000 allow privileged binary replacement. **Do not expose port 4000 to WAN or untrusted LAN**; firewall it. Existing web UI is unauthenticated.
* Release integrity is protected by HTTPS and SHA-256 computed server-side. For higher assurance implement independently signed release manifests.
* Installer does not change `settings.ini`, `services.txt` or `doh-only.txt`.

* `UpdateServer = https://dnsrouting.gm-world.ru/updates.php` in `settings.ini` controls both daily and manual update checks. Editable in the web UI. HTTPS is required; binary URLs must use the same hostname as the selected update server.

* `/tmp` space is checked before download using HTTP Content-Length when available, and before every write during streaming (also when Content-Length is absent or wrong). At least **1 MiB** remains free in `/tmp`; if insufficient, downloading stops, the partial temporary file is deleted, and the running service/binary remains untouched. `/tmp` and flash are checked separately.
